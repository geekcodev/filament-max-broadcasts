# v1.1.0

Плагин переведён на форму реестра чатов `laravel-max-client` 1.2: одна строка на чат вместо строки на пару
«пользователь-чат». Это снимает долговое решение пункта 1 плана — constraint стал точным, а код работает с обеими
формами реестра.

## Новое

**Адаптер реестра чатов.** Появился `Support\ChatRegistry` — единственное место в коде, которое знает про форму
реестра ядра. Он прячет различия версий: связь чат-пользователь (`maxUser` на форме 1.1 против pivot `max_chat_users`
на 1.2), колонку `user_id` и ключ строки (`id` против `chat_id`), а также `title`, которого на 1.1 просто нет.
Переведены пять мест: выбор получателей, таблица согласий, relation manager получателей, `BroadcastService` и джоба
запроса согласия. Снаружи адаптера обращаться к `maxUser`, `user_id` и `title` чата больше нельзя.

**Знаковые идентификаторы получателей.** Новая миграция `2026_10_02_000001_make_broadcast_recipient_ids_signed`
переводит `max_broadcast_recipients.chat_id` и `user_id` из `unsigned` в знаковый `BIGINT`. Группы и каналы MAX имеют
отрицательные идентификаторы, и без этого MySQL отвергал бы рассылку в канал, а на PostgreSQL тип и так знаковый
(миграция приводит оба драйвера к одному виду; gotcha к формату данных в §9
`AGENTS.md`). На SQLite тип не меняется — там знаковость не хранится. Историческая миграция не редактировалась:
структура колонок меняется новой ad-hoc миграцией, как требует §2 `AGENTS.md`.

## Изменение (BC)

Минимальная версия `laravel-max-client` поднята до `^1.2.0`, `max-php-client` — до `^1.1.8`. Установка
`laravel-max-client` 1.1.x больше не удовлетворяет constraint, хотя код на ней работает.

Для хостов, обновляющихся с 1.1.x, порядок обязателен:

```bash
composer require geekcodev/laravel-max-client:^1.2.0
php artisan migrate      # новая форма реестра: max_chats по chat_id + таблица max_chat_users
php artisan max:upgrade  # перенос данных реестра из старой формы в новую
```

Без `max:upgrade` таблица `max_chat_users` остаётся пустой, и плагин не найдёт ни одного получателя. Обратный шаг в
release notes ядра не предусмотрен, поэтому порядок менять нельзя.

## Затронутые сценарии

Выбор получателей, рассылка сегментам, список сегментов, журнал согласий, отправка запроса согласия и повтор
рассылки работают без изменений интерфейса. В журнале согласий для групп и каналов теперь видно `title` из реестра
1.2 там, где раньше показывался голый `chat_id`.

Побочная правка: `ChatSelectionField::optionLabels()` отбрасывает нескалярные значения до запроса, а не при
подстановке подписей. Раньше массив выборов с объектом или вложенным массивом ронял `whereIn`; теперь такие значения
пропускаются.

## Качество

235 тестов (610 assertions) — набор одинаковый для обеих форм реестра, тестовая фикстура `tests/Fixtures/Chats.php`
создаёт чаты и пользователей по форме, установленной в `max_chats`. Добавлен `tests/Unit/Support/ChatRegistryTest.php`
(38 тестов) на обе формы и тест записи отрицательного `chat_id` получателя.

Gate прогнан на обеих формах: на 1.2.0/1.1.8 — PHPStan level max 0 ошибок, PSR-12 0 файлов, покрытие 97.84% строк
(91.35% методов) при пороге 95%; на legacy 1.1.1/1.1.0 — те же зелёные статика и линт, покрытие 96.28% строк
(89.73% методов). `composer security-audit` в этой сессии выполнить не удалось: `repo.packagist.org` был недоступен из
контейнера (`curl error 28`), поэтому проверка уязвимостей остаётся за CI.
