# v1.1.2

Согласие на рассылку переехало в сегменты, в сегменты попадают только диалоги, рассылка требует сегменты или
получателей, а в селектах появились «Выбрать всех» и бейджи с числом получателей. Также исправлены кнопки «Создать» по
правам и добавлены страницы и таблицы для просмотра сегментов и связанных согласий. Общий журнал согласий получил фильтр
по сегменту, а согласия теперь переживают удаление сегмента.

## Новое

**Запрос согласия по сегменту.** Кнопка «Запросить согласие» перенесена со списка рассылок в страницу сегмента и в
строку таблицы сегментов. Запрос «Вы согласны получать рассылку «название»?» с кнопками «Да» и «Нет» уходит активным
диалогам, которые ещё не ответили на этот сегмент. Ответы попадают в согласия этого сегмента. Стартовый сегмент «Новости
и акции» остаётся обычным сегментом.

**Сообщение с опросом исчезает после ответа.** После нажатия «Да» или «Нет» бот удаляет сообщение с вопросом из чата.
Если удалить его не удалось, кнопки убираются правкой сообщения: повторно нажать опрос нельзя, а согласие всё равно
записано.

**Сегменты только из диалогов.** В сегмент нельзя добавить группу или канал: форма и сервер отклоняют такие чаты.
Рассылка по сегменту отправляется только диалогам. Группы и каналы выбираются в получателях при создании рассылки.
Старые сегменты с группами не изменяются, но в сегменте и в таблице сегментов показывается предупреждение.

**Сегменты с получателями в рассылке.** В селекте сегментов при создании рассылки показаны только сегменты с активными
диалогами. Рядом с названием выводится бейдж с числом получателей.

**Выбрать всех.** Селекты сегментов и получателей рассылки получили действие «Выбрать всех». Оно выбирает все подходящие
чаты без лимита в 50 и сохраняет поиск. Подписи выбранных значений выводятся полностью.

**Бейджи чатов и пользователей.** Получатели сегмента, `chat_id` и `user_id` в таблицах согласий и получателей рассылки
выводятся бейджами, как в селектах форм: цветной бейдж типа чата, имя и ID.

**Страница просмотра сегмента.** У ресурса «Сегменты» появилась страница с названием, описанием, числом получателей,
датой создания и списком чатов с именами из реестра. В таблице сегментов добавлено действие «Просмотр». Правка и
удаление по праву `broadcasts.manage`, сама страница по `broadcasts.view`.

**Согласия в сегменте.** На страницах просмотра и правки сегмента появилась таблица согласий на рассылку: только
согласия этого сегмента, поиск по имени собеседника, удаление по праву `broadcasts.manage`.

**Фильтр и история согласий.** В общем журнале «Согласия» появился фильтр по сегменту, включая вариант «Без сегмента».
При удалении сегмента его согласия больше не теряются и не блокируют удаление: записи остаются в журнале с пустым
`segment_id`. Исправлен дефект схемы: колонка была `NOT NULL` при внешнем ключе `ON DELETE SET NULL`, из-за чего
удаление сегмента с ответами падало, а на MySQL такая таблица могла не создаться на чистой установке.

**Кнопка «Создать» по правам.** На списке сегментов кнопка появилась, на списке рассылок скрыта от пользователей без
права `broadcasts.create`.

## Изменение (BC)

Публичные сигнатуры не менялись. Добавлена миграция `0000_03_000008`: она делает `max_broadcast_consents.segment_id`
nullable, новые установки получают ту же схему сразу из create-миграции. Поведение и значения по умолчанию изменились:

- **Пустой выбор рассылки.** Рассылка без сегментов и без получателей больше не отправляется «всем активным чатам»:
  `BroadcastService::create()` бросает `InvalidArgumentException`, форма требует заполнить хотя бы одно поле. Повтор
  рассылки без снимка получателей показывает уведомление и не создаёт новую рассылку. Изменение относится к поведению по
  умолчанию, поэтому в minor-релиз его было бы логичнее вынести отдельно; в v1.1.2 оно выпущено по решению владельца.
- **Тексты и кнопки запроса согласия по умолчанию.** `consent.request_message` стал «Вы согласны получать рассылку «:
  segment»?», `consent.button_text_opt_in` / `button_text_opt_out` — «Да» / «Нет». Хосты, которые опубликовали конфиг,
  сохранят старые значения; при желании их нужно обновить вручную.
- **Кнопка «Запросить согласие» перенесена.** На списке рассылок её больше нет, она есть на странице сегмента и в
  таблице сегментов с тем же правом `broadcasts.create`.
- **Опросы согласия только по сегменту.** Payload кнопок всегда `consent:<segmentId>:<action>`. Опросы с payload
  `consent:<action>` (отправленные до этой правки) больше не обрабатываются — их нужно удалить или проигнорировать.
- **Сообщение с опросом удаляется.** После нажатия «Да» или «Нет» бот удаляет исходное сообщение с вопросом
  (`deleteMessage`). Если удалить не удалось — убирает кнопки правкой через `editMessage`, чтобы повторное нажатие было
  невозможно.
- **`ConsentPoll::buttonRows()` без сегмента.** Метод контракта теперь возвращает пустой список: кнопки опроса строятся
  только через `buttonRowsFor($segmentId)`, а `payload()` принимает обязательный `segmentId`. Прямой вызов
  `buttonRows()` больше не даёт кнопок — отправить опрос без сегмента нельзя.
- **Сегменты с группами.** Группы в старых сегментах не удаляются, но при рассылке по сегменту не получают сообщение.

## Затронутые сценарии

- Администратор с `broadcasts.create` открывает сегмент, запускает запрос согласия и видит число отправленных запросов;
  ответы «Да» и «Нет» попадают в этот сегмент.
- Чат, который уже ответил на запрос сегмента, не получает его повторно, но получает запрос другого сегмента.
- После нажатия «Да» или «Нет» сообщение с вопросом исчезает из чата; если удалить его не удалось, кнопки пропадают, и
  повторно нажать опрос нельзя.
- Старый опрос с payload `consent:opt_in` больше не обрабатывается: согласие не записывается, бот не отвечает на
  нажатие.
- Пользователь только с `broadcasts.view`: кнопок «Запросить согласие», «Создать», «Правка» и «Удалить» нет, прямой URL
  страницы создания даёт 403.
- Рассылка только по сегменту, только по получателям или по обоим полям создаётся; без обоих полей — ошибка валидации.
- Рассылка по сегменту с группой в старых данных не уходит группе; в сегменте видно предупреждение.
- Сегмент, выбранный в форме и ставший пустым (диалоги выбыли), не блокирует создание рассылки: подпись без бейджа,
  рассылка уйдёт только активным диалогам сегмента (если их нет и получателей нет — рассылка создаётся с нулём
  получателей).
- Администратор удаляет сегмент, в котором уже есть ответы: сегмент удаляется, согласия остаются в общем журнале с
  пометкой «Без сегмента», фильтр по этому варианту показывает их.
- В селекте сегментов рассылки нет сегментов без получателей; у каждого сегмента виден бейдж с числом диалогов.
- Обновление с v1.1.1: выполнить `php artisan migrate` (миграция `0000_03_000008` делает `segment_id` nullable) и при
  желании обновить тексты запроса в конфиге.
