# Удаление сообщения с опросом согласия и отказ от legacy-payload

## Проблема

После нажатия «Да» или «Нет» сообщение с запросом согласия оставалось в чате: слушатель убирал из него кнопки через
`editMessage`, но сам текст опроса сохранялся. Кроме того, `HandleConsentCallback` принимал legacy-payload
`consent:<action>` без сегмента и относил такой ответ к стартовому сегменту «Новости и акции», хотя с переходом на
сегменты все новые опросы содержат `consent:<segmentId>:<action>`. Пользователь подтвердил, что старые опросы уже
нажаты, поэтому legacy-ветку можно удалить до релиза v1.1.2 без периода депрекейта.

## Решение

- `HandleConsentCallback` принимает только payload с сегментом: регулярное выражение требует
  `consent:<segmentId>:<action>`. Payload без сегмента, чужие callback'и и неизвестные действия игнорируются без вызова
  MAX API; стартовый сегмент при этом не создаётся.
- После записи согласия исходное сообщение удаляется через `ApiClient::deleteMessage($messageId)`. Идентификатор берётся
  из `update.messageId`, при отсутствии — из `callback.message.body.mid`; без идентификатора удаление пропускается.
- Если удалить сообщение не удалось, выполняется fallback: `editMessage` с прежним текстом без клавиатуры. Опрос нельзя
  нажать повторно, а согласие уже записано. Если текста нет, fallback пропускается с предупреждением в лог.
- `ConsentPoll::buttonRows()` теперь возвращает пустой список: контракт требует метод, но опрос без сегмента отправить
  нельзя. Кнопки строятся только через `buttonRowsFor(int $segmentId)`, `payload()` принимает обязательный `segmentId`.
- Публичные методы `ConsentService` с необязательным `segmentId` и `findSegment(null)` сохранены для обратной
  совместимости с хостами: без сегмента они работают со стартовым сегментом, но callback этот путь больше не использует.
- Обновлены `README.md`, `AGENTS.md` (§5, §9, gotcha 25), комментарий конфига и release-notes v1.1.2.

## Тесты

- `HandleConsentCallbackTest`: opt-in и opt-out удаляют сообщение (`DELETE /messages?message_id=...`), запись попадает в
  сегмент из payload; удаление пропускается без идентификатора; при ошибке удаления выполняется `PUT /messages` без
  кнопок, при отсутствии текста fallback пропускается; согласие фиксируется при сбоях удаления, подтверждения и
  `sendAnswer`; payload `consent:opt_in` игнорируется.
- `ConsentPollTypeTest`: `buttonRows()` пуст, `buttonRowsFor()` и `payload()` несут сегмент, тексты кнопок берутся из
  конфига.

## Нюансы

- По спецификации MAX в диалогах бот может удалять только свои сообщения, а запросы согласия уходят только активным
  диалогам, поэтому `deleteMessage` допустим. Ограничение 2 удаления в секунду на чат обеспечивает ядро.
- Подтверждение в чат и `sendAnswer` оставлены как раньше: они не зависят от результата удаления.
- Удаление legacy не меняет формат новых кнопок и не затрагивает журнал согласий: записи стартового сегмента остаются,
  но новые ответы по старым кнопкам больше не появляются.
- Порог покрытия 95% не менялся; покрытие снизилось с 97.34% до 97.02% из-за новых защитных веток удаления и fallback.
