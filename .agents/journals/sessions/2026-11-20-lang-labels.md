# Локализация: ID вместо технических имён полей

## Проблема

В подписях таблиц согласий и получателей выводились технические имена полей `MAX chat_id` и `MAX user_id`. В форме
рассылки оставалась ссылка на `config buttons.per_type`, а лимит текста назывался «лимит API». Для пользователя панели
это внутренние детали, а не понятные подписи.

## Решение

- `consent_table.chat_id` / `recipients.chat_id` → «ID чата», `user_id` → «ID пользователя»; в английской локали —
  `Chat ID` и `User ID`.
- `consent_table.name` → «Имя чата» / `Chat name`, `recipients.name` → «Имя пользователя» / `User name`.
- `form.type_helper` больше не упоминает `config buttons.per_type`.
- `form.text_helper`: «Лимит API» → «Лимит сообщения» (`Message limit`).
- `form.recipients_section_description` описывает актуальные поля: сегменты и/или группы и каналы.
- `segment.view.recipients_section_description` уточняет, что рассылка уходит согласившимся диалогам.
- `notifications.repeat_empty` больше не говорит «у неё не было получателей»: повтор может быть пуст и из-за отказов.

## Тесты

Код не менялся; набор языковых ключей `ru` и `en` сверен программно (128 ключей, расхождений нет). PHPUnit 335/335 (933
assertions).

## Нюансы

- Технические `chat_id`/`user_id` остались только в коде, конфиге, логах и документации для разработчиков — в подписях
  UI их больше нет.
- Брендовые упоминания MAX оставлены там, где это полезно пользователю (описание возможностей редактора).

## Gate

Код не менялся, Gate не перезапускался. Предыдущий прогон: lint 0/111, PHPStan max 0, 335 тестов, покрытие 96.69%, audit
0.
