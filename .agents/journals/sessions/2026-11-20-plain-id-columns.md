# ID чата и пользователя — обычным текстом

## Проблема

В таблицах согласий и получателей `chat_id` показывался бейджем типа чата и бейджем `ID: n`, а `user_id` — бейджем
`ID: n`. Для ID это лишний визуальный шум: тип чата полезен в селектах, но не в колонке идентификатора.

## Решение

- В `BroadcastConsentsTable` и `BroadcastRecipientsRelationManager` колонки `chat_id` и `user_id` выводят только число
  обычным текстом, без `fi-badge` и без префикса `ID:`.
- Удалены `ChatSelectionField::idBadge()` и приватные `chatBadges()`; бейдж типа остался в подписях селектов и infolist
  сегмента, где он помогает выбрать чат.
- Тесты обновлены: проверяют наличие ID и отсутствие `ID:`, тип чата в этих колонках больше не выводится.

## Тесты

335 тестов / 937 утверждений. Обновлены тесты журнала согласий и таблиц получателей/согласий сегмента.

## Нюансы

- В селектах чатов (`ChatSelectionField::labelFor`) бейдж типа и `(ID: n)` остались: там это часть выбора, а не колонка
  идентификатора.
- В infolist сегмента список получателей по-прежнему показывает тип, имя и ID — это просмотр состава, а не таблица
  идентификаторов.
