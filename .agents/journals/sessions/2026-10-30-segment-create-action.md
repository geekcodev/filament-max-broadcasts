# Кнопка «Создать» на списках сегментов и рассылок

## Проблема

На списке сегментов не было кнопки «Создать», хотя страница создания зарегистрирована и доступна по прямому адресу. На
списке рассылок кнопка, наоборот, была видна пользователю с одним `broadcasts.view`, а клик давал 403 на странице
создания: сервер защищён, UI — нет (fail-open в интерфейсе).

Обе причины — поведение Filament v5. Базовый `ListRecords` больше не объявляет header-действий, поэтому `CreateAction`
нужно добавлять в `getHeaderActions()` вручную. Авторизация действий идёт через
`Page::getDefaultActionAuthorizationResponse()`
→ `get_authorization_response('create', $model)`, то есть через политику модели; политик в пакете нет, и без явного
`->authorize(...)` действие разрешено всем, кто вправе открыть страницу. Переопределённый `Resource::canCreate()` в этом
пути не участвует — он остаётся проверкой `CreateRecord::authorizeAccess()`.

## Решение

`ListBroadcastSegments` объявляет `CreateAction::make()->authorize($createPermission)`. В `ListBroadcasts` чтение права
вынесено в переменную `$createPermission` в начале `getHeaderActions()` и использовано и для `CreateAction`, и для
действия «Запросить согласие», чтобы конфиг не читался дважды. Серверные проверки и `Resource::canCreate()` не менялись,
новых прав не вводилось.

## Тесты

Сначала воспроизводящие тесты (красные по описанным причинам), затем фикс:

- `BroadcastSegmentResourceTest`: видимость кнопки при `broadcasts.create`, скрытие при одном `broadcasts.view`, 403 на
  прямой `GET` страницы создания;
- `BroadcastResourceTest`: те же три проверки для списка рассылок. До фикса падал тест на скрытие: действие без
  `authorize` разрешено всем.

Тест на скрытие держит форму фикса: если убрать `->authorize(...)`, он снова станет красным.

## Нюансы

- В плане был указан Filament v5.10.3; локально после `composer update` стоит v5.11.0 — поведение то же, проверено
  тестами.
- Право для сегментов отдельно не выделялось: модель остаётся «одно `broadcasts.create` на рассылки, сегменты и запрос
  согласия». Отдельное право расширило бы публичный контракт и потребовало бы синхронизации у хостов.
- Миграций и изменений конфига нет, у существующих установок после обновления пакета ничего выполнять не нужно.
- Новый gotcha 24 в `AGENTS.md` фиксирует причину, чтобы `authorize()` не потерялся при следующей правке действий.
