# Получатели и согласия сегмента как вкладки

## Проблема

Форма сегмента содержала селект чатов с «Выбрать всех». Для больших аудиторий это неудобно: чипы на каждого получателя
тормозят форму, «Выбрать всех» разворачивался в тысячи значений, а управлять составом (найти, снять, добавить) можно
было только через тот же селект. Согласия жили в relation manager внизу страницы, а получатели — в форме.

## Решение

- Форма сегмента содержит только блок «Основное»: название и описание на всю ширину.
- У сегмента появились страницы-вкладки через `getRecordSubNavigation`: «Просмотр», «Основное», «Получатели»,
  «Согласия».
- `ManageBroadcastSegmentRecipients` — таблица всех активных диалогов с поиском, сортировкой, фильтром «Только
  выбранные» и чекбоксами. В таблице есть колонка согласия по текущему сегменту: часы (pending), зелёная галочка
  (opt_in), красный крест (opt_out), пусто при отсутствии записи; состояние читается коррелированным подзапросом, без
  N+1. Текущий состав сегмента предвыбран из `chat_ids`. «Выбрать всех» и «Снять выделение» работают через клиентские
  методы таблицы (`selectAllRecords()`/`deselectAllRecords()`), поэтому состояние чекбоксов не расходится с Livewire.
  «Сохранить выбранных» — действие таблицы: пишет `chat_ids`, сохраняя старые не-диалоговые и неактивные ID, чтобы не
  терять данные; кнопка работает и при пустом выборе (очистка сегмента). В подзаголовке — общее число активных диалогов.
- `ListBroadcastSegmentConsents` — отдельная страница журнала сегмента на базе
  `BroadcastConsentsTable::configureForSegment`.
- `BroadcastConsentsRelationManager` удалён; `BroadcastConsentResource` остаётся общим журналом.
- Из `ChatSelectionField` удалены `SELECT_ALL`, `allIds()`, `expandState()` и related-логика: поле осталось для выбора
  групп и каналов в форме рассылки.
- `BroadcastSegmentInfolist` больше не рендерит полный список получателей: показывает количество и ссылку на вкладку
  «Получатели» (важно для больших сегментов).
- Создание и правка сегмента больше не трогают `chat_ids`; состав меняется только на вкладке получателей.

## Нюансы

- «Выбрать всех» — это клиентская операция таблицы: Filament сам хранит режим «все выбраны» без массива из 10 000 ID.
  Сохранение — действие таблицы; клиентский обработчик таблицы синхронизирует это состояние с сервером перед запуском.
- Фильтр «Только выбранные» учитывает текущее состояние чекбоксов, включая режим «все выбраны».
- Снятие с учёта активного диалога удаляет его из сегмента; неактивные диалоги и старые группы сохраняются и остаются
  помеченными предупреждением.
- `resources/views/pages/` — первые Blade-файлы пакета, только обёртки `{{ $this->table }}`.
