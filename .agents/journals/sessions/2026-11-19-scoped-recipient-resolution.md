# Точечная выборка получателей по chat_id

## Проблема

`ConsentRequestService` и `BroadcastService` резолвили **все** активные чаты реестра и фильтровали их в PHP: опрос
сегмента из десяти человек читал весь реестр, а при создании рассылки это повторялось. Плюс `ChatRegistry::userId()` в
цикле по получателям лениво подгружал `chatUsers` — N+1 запросов на форме реестра 1.2.

## Решение

- `BroadcastRecipientsResolver::resolveForChatIds(list<int>)`: читает только запрошенные `chat_id` чанками по 500,
  фильтрует `status = active`, подгружает пользователей `ChatRegistry::withUsers()`, дедуплицирует и сортирует по
  `last_activity_at`.
- Для подклассов с переопределённым `resolve()` по умолчанию работает безопасный путь: `resolve()` + фильтр по id, то
  есть правила хоста сохраняются. Быстрый путь включается переопределением `supportsScopedResolution()`, если подкласс
  не меняет правила выбора.
- `ConsentRequestService::eligibleChats()` переведён на scoped-выборку по `chat_ids` сегмента; фильтры по ответившим и
  типу «диалог» остались в сервисе.
- `BroadcastService::resolveChats()` тоже использует `resolveForChatIds()`: кандидаты — согласившиеся диалоги и явные
  группы/каналы; без сегментов — только явные id.

## Тесты

348 тестов / 954 утверждения. Добавлены: scoped-выборка возвращает только запрошенные активные чаты в нужном порядке,
пользователи подгружены заранее, подкласс с переопределённым `resolve()` сохраняет свои правила. Моки резолвера в
`BroadcastServiceTest` получили ожидание `resolveForChatIds`.

## Нюансы

- На форме реестра 1.1.x отдельного индекса по `chat_id` может не быть: выборка по списку id всё равно вернёт мало строк
  и не загрузит весь реестр в память, но сканирование таблицы останется. Хосту стоит добавить индекс, если сегменты
  большие.
- Контракт для кастомных резолверов: если `resolve()` переопределён и правила важны, оставьте безопасный путь; если
  правил нет, можно включить `supportsScopedResolution()`. Зафиксировано в `AGENTS.md` и release notes.
- Опрос по-прежнему резолвит кандидатов дважды: при нажатии (для количества) и в задаче (для свежести). Обе выборки
  теперь точечные.
