# Удаление завершённых планов

## Проблема

В `.agents/plans/` накопились четыре завершённых плана, один из которых (`PLAN-consent-callback.md`) до сих пор был
помечен «идёт реализация», хотя реализован в v1.1.x. `AGENTS.md` при этом ссылался на `PLAN-filament-max-broadcasts.md`
как на активный план, хотя он закрыт. Завершённые планы дублируют журнал и release notes и вводят в заблуждение.

## Решение

- Удалены завершённые `PLAN-filament-max-broadcasts.md`, `PLAN-consent-callback.md`,
  `2026-10-30-consent-per-segment.md`, `2026-10-30-segment-create-action.md`. Оставлен активный
  `2026-11-19-residual-review-notes.md` (в нём только блокеры релиза v2.0.0).
- В `AGENTS.md` правило 1, правило 12, §4.1, таблица «Что куда писать» и чек-лист переписаны на «активный план в
  `.agents/plans/`»; зафиксировано правило: после закрытия всех пунктов итоги переносятся в журнал и release notes, файл
  плана удаляется. Историю хранят журнал, release notes и git.

## Тесты

Код не менялся, тесты не запускались.

## Нюансы

- В исторических записях журнала остались ссылки на удалённые файлы планов — это история; содержимое доступно в git.
- `AGENTS.md` больше не называет конкретный файл активного плана, чтобы ссылка не устарела после его закрытия.

## Gate

Не запускался: изменения только в документации и рабочей памяти. Предыдущий прогон кода — зелёный (338 тестов, покрытие
96.69%, PHPStan 0, audit 0).
