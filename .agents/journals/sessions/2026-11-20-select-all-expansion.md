# «Выбрать всех» сразу раскрывается в выбранные чаты

## Проблема

В форме сегмента «Выбрать всех» был служебным значением селекта: после клика в поле появлялся сам пункт «Выбрать всех»,
а реальные чаты подставлялись только при сохранении (`dehydrateStateUsing`). Пользователь ожидал увидеть в поле
выбранными все доступные чаты, а не служебный чип.

## Решение

- `ChatSelectionField` получил `->live()` и `afterStateUpdated`: если в state появилось `SELECT_ALL`, он сразу
  заменяется результатом `expandState()` — списком всех активных чатов с учётом области (`dialogsOnly`/
  `nonDialogsOnly`).
- Служебное значение после раскрытия в state не остаётся, поэтому чипы показывают конкретные чаты; повторного
  срабатывания нет — на раскрытом массиве `SELECT_ALL` уже отсутствует.
- `dehydrateStateUsing` оставлен как fallback для программной установки значения без live-обновления.
- Подписи выбранных значений по-прежнему разрешает `getOptionLabelsUsing`, поэтому чаты за пределами лимита 50 вариантов
  отображаются именем и ID, а не сырым числом.

## Тесты

- Unit: селект помечен `isLive()`; разворачивание `expandState` уже покрыто.
- Feature: после установки `SELECT_ALL` state содержит все активные диалоги и не содержит служебное значение; сохранение
  сегмента по-прежнему пишет только диалоги. Тесты используют `set('data.chat_ids', ...)`, потому что тестовый
  `fillForm()` отключает хуки состояния и обрезает числовые ключи массива — это особенность хелпера, а не поведения UI.
- Итог: 360 тестов / 1042 утверждения.

## Нюансы

- При большом числе чатов в поле окажется столько же чипов: это ожидаемая цена явного выбора. Лимит 50 касается только
  вариантов в выпадающем списке, не выбранных значений.
- «Выбрать всех» осталось только в форме сегмента; в получателях рассылки его нет.
