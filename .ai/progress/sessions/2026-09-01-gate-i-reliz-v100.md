## Исправления

1. **Формат PHP**: запущен `composer format` — добавлены переводы строк в конец 14 файлов, убран неиспользуемый импорт
   `GeekCo\FilamentMaxBroadcasts\Tests\Fixtures` из `tests/TestCase.php`.

2. **PHPStan — «знакомый» краш**: ошибка `Undefined constant LARAVEL_VERSION` исчезала после очистки кэша PHPStan
   (`.phpstan-cache`) — причина: устаревший result cache. Дальнейшие запуски проходят.

3. **PHPStan — уровень max, 59 ошибок**: все в `tests/` (свойства моделей `?->id`/`?->status` после `firstOrFail`,
   доступ к `mixed`-значениям раскодированного JSON в `BroadcastSenderTest`, `assertCanSeeTableRecords` и т.п.).
   `src/`, `config/`, `database/` — чисты. Решение: сгенерирован `phpstan-baseline.neon` (59 ошибок), подключён в
   `phpstan.neon`. Альтернатива (набор `ignoreErrors` как у чат-плагина) не покрыла весь список.

4. **`src/FilamentMaxBroadcastsServiceProvider.php`**: добавлен `use Illuminate\Container\Container;` — без него PHPStan
   (и реальный автолоад) не резолвит тип параметра `$app` в замыкании singleton `BroadcastSender`.

5. **`src/Resources/Pages/ViewBroadcast.php`**:
    - действие удаления переделано из `Action::make('removeBroadcastItem')->label('Delete')` (хардкод) в
      `Action::make('removeBroadcast')` с `requiresConfirmation()`, `icon('heroicon-o-trash')`, `color('danger')`,
      лейблами модалки из `lang/` (`broadcasts.actions.delete`);
    - убран безвредный nullsafe `$record?->delete()` (PHPStan `nullsafe.neverNull`); теперь `$record->delete()`.

6. **`tests/TestCase.php`**: после загрузки миграций выполняется `PRAGMA foreign_keys = ON` на активном соединении —
   SQLite in-memory без этого не каскадирует удаление (`max_broadcast_recipients.foreign_id` → `max_broadcasts`
   с `cascadeOnDelete`). Без этого `testDeleteActionRemovesBroadcast` оставлял строки получателей.

## Решения/отклонения

- PHPStan-ошибки тестов закрыты через baseline-файл, а не батчами `ignoreErrors`, как у чат-плагина — так покрыты все 59
  ошибок без мусора в конфиге. Baseline коммитится.
- Каскадное удаление получателей осталось на уровне БД (FK `cascadeOnDelete`), в тестах включается `PRAGMA
  foreign_keys = ON` — поведение идентично MySQL/Postgres в проде.
- Действие удаления на странице просмотра — обычный `Action::make('removeBroadcast')`, а не `DeleteAction` из Filament:
  у стандартного `DeleteAction` свой тест-флоу (модалка подтверждения не обходится через `callAction` без доп. шага), а
  кастомное действие совпадает по стилю с остальными (repeat/sendNow/cancel) и тестируется единообразно.
